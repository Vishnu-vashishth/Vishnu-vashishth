I spend most of my time in the unglamorous half of the stack — the part that has to be correct at 3am. Lately that means **payment infrastructure**: idempotent checkout flows, provider webhooks that survive being delivered twice or not at all, subscription lifecycles, and event delivery between services that can't afford to lose a message.

## `~/now`

<details open>
<summary><b>Payment microservice</b> — one checkout, many products</summary>
<br/>

A provider-agnostic payment service that several products share instead of each one growing its own half-correct Stripe integration.

- **One provider config, per-app plans** — apps differ as data, never as branches in the service
- **Idempotent settlement** — a webhook delivered twice settles once; a webhook never delivered gets recovered
- **gRPC contracts** between the payment service and the apps that consume it
- **Subscription lifecycles** — renewals, one-time-payment upgrades, grace periods

</details>

<details>
<summary><b>AI chat platforms</b> — the backend behind the conversation</summary>
<br/>

Character-driven chat products: conversation state, suggestion generation, prompt plumbing, and the migrations that keep years of message history honest. Mongo at a size where query plans stop being academic.

</details>

<details>
<summary><b>Observability that earns its keep</b></summary>
<br/>

Structured logs to Axiom, dashboards that answer questions someone actually asked, and feature flags via GrowthBook so a rollout is a decision rather than a deploy.

</details>
